## Опис
Перетворює цільове ключове слово й пошуковий інтент на структурований бриф контенту (пропоновані заголовки, питання для відповіді, нотатки про пошуковий інтент, пропозиції внутрішнього лінкування) для автора, щоб писати на його основі — інструмент планування для етапу «що має покривати ця стаття», відмінний від «outline-to-draft-blog-expander» (writing-and-content), який розгортає план у прозу, коли бриф/план уже існує.

## Коли використовувати
- Ти інструктуєш автора (внутрішнього чи фрилансера) щодо нової SEO-статті й хочеш структурований бриф замість того, щоб просто дати ключове слово.
- У тебе є цільове ключове слово, але ти не досліджував, що реально має покривати повноцінна, відповідна інтенту стаття.
- Ти аудитуєш структуру наявної статті проти того, що мав би включати бриф для цього ключового слова, щоб знайти прогалини контенту.

## Промпт

```
Ти генеруєш SEO-бриф контенту для цільового ключового слова: аналіз пошукового інтенту, пропоновану структуру заголовків, конкретні питання, на які стаття має відповісти, і пропозиції внутрішнього лінкування — достатньо для автора, щоб писати без додаткового дослідження обсягу.

Цільове ключове слово: {{KEYWORD}}
Контекст сайту/бренду: {{SITE_CONTEXT}}
Наявні пов'язані сторінки (для внутрішнього лінкування): {{RELATED_PAGES}}

Інструкції:
1. Вкажи ймовірний пошуковий інтент за {{KEYWORD}} — інформаційний, комерційно-дослідницький, транзакційний чи навігаційний — і що це означає для кута подачі статті (напр., комерційно-дослідницький запит потребує порівняльного/оціночного контенту, не how-to).
2. Запропонуй структуру заголовків (H1 + H2, з H3 там, де секції явно потрібна підрозбивка), що вичерпно покриває інтент — кожен заголовок має відповідати реальній підтемі, яку захотів би бачити шукач із цим інтентом, а не загальним заповнювальним секціям.
3. Перелічи конкретні питання, на які стаття має відповісти, сформульовані так, як їх реально поставив би шукач (не переформульовані варіації ключового слова) — вони мають відповідати тому, що людина реально ввела б у пошуковий рядок чи запитала б колегу.
4. Пропонуй внутрішні посилання на {{RELATED_PAGES}} лише там, де є справжній тематичний зв'язок із конкретною секцією запланованої статті — не пропонуй посилання лише щоб збільшити їх кількість.
5. Зазнач реалістичний орієнтовний діапазон довжини на основі інтенту й сигналів конкурентності, що випливають із {{KEYWORD}} (широкий, конкурентний термін зазвичай потребує повнішого покриття, ніж вузький, довгохвостий) — але познач це як приблизний орієнтир, не правило, оскільки реальне дослідження конкуренції недоступне цьому промпту.
6. Якщо {{KEYWORD}} неоднозначний (кілька правдоподібних пошукових інтентів), скажи це і або запитай, для якого інтенту робити бриф, або надай короткі нотатки для кожного правдоподібного інтенту, а не вгадуй один.

Формат виводу: Markdown із секціями: `## Пошуковий інтент`, `## Пропонована структура заголовків`, `## Питання для відповіді`, `## Пропозиції внутрішнього лінкування`, `## Цільова довжина`.
```

## Змінні
- `{{KEYWORD}}` — цільове ключове слово/фраза. Обов'язково.
- `{{SITE_CONTEXT}}` — що таке сайт/бренд і його загальна аудиторія, щоб кут подачі брифу пасував (напр., бриф для сайту для початківців відрізняється від сайту для технічної/експертної аудиторії). Обов'язково.
- `{{RELATED_PAGES}}` — наявні сторінки/URL з однорядковою нотаткою теми кожної, для пропозицій внутрішнього лінкування. Необов'язково — пропусти, якщо ще недоступно; бриф все одно працює без пропозицій лінкування.

## Приклад
**Вхід:** `{{KEYWORD}}` = «найкраще ПЗ для управління проєктами для малих команд» · `{{SITE_CONTEXT}}` = «B2B SaaS-блог для інструменту управління проєктами, орієнтованого на агенції та малі команди» · `{{RELATED_PAGES}}` = «/features/time-tracking, /pricing»

**Вихід (уривок):**
```
## Пошуковий інтент
Комерційно-дослідницький — шукач порівнює варіанти перед вибором, а не шукає визначення чи вже готовий купити конкретний названий продукт. Стаття має бути справжнім порівнянням/оцінкою, не пітчем одного продукту, замаскованим під «топ» список.

## Пропонована структура заголовків
- H1: Найкраще ПЗ для управління проєктами для малих команд у 2026
- H2: Що малим командам насправді потрібно від PM-ПЗ (відрізняється від enterprise-потреб)
- H2: Порівняння топ-варіантів
  - H3: [Категорія інструментів 1 — напр., легкі/прості]
  - H3: [Категорія інструментів 2 — напр., багатофункціональні]
...
```

## Поради та варіації
- Коли бриф готовий, передай його в «outline-to-draft-blog-expander» (writing-and-content) як вхідний план — структура заголовків цього промпту напряму мапиться на змінну `{{OUTLINE}}` того промпту.
- Для аудиту прогалин контенту наявної статті замість нового брифу, вклей поточні заголовки статті як контекст у стилі {{RELATED_PAGES}} й прямо запитай, що бриф мав би включити, чого статті бракує.
- Цей промпт не має доступу до реальних даних обсягу пошуку, конкуренції чи SERP — для важливих рішень щодо ключових слів перевіряй інтент і конкурентність через реальний SEO-тулінг перед значними зусиллями написання.
