## Опис
Рекомендує конкретний мікс хештегів — невелику кількість високооб'ємних/широких тегів для охоплення, кілька нішевих тегів середньої конкуренції та 1-2 брендових/спільнотних теги — замість загального «використовуй 5-10 релевантних хештегів», і позначає теги, що виглядають тематично релевантними, але реально виводять аудиторію, не пов'язану з реальним змістом посту.

## Коли використовувати
- Ось-ось опублікуєш пост і хочеш свідомий мікс хештегів замість вгадування чи повторного використання того самого списку тегів у кожному пості незалежно від теми.
- Пост показав погані результати, і підозрюєш, що хештеги притягнули не ту аудиторію (високі покази, низька релевантна залученість), а не що сам контент був слабким.
- Будуєш повторювану стратегію хештегів для акаунту й хочеш задокументувати обґрунтування рівнів тегів, а не просто список для копіювання.

## Промпт

```
Ти рекомендуєш мікс хештегів для конкретного посту, балансуючи охоплення проти релевантності. Ти не просто перераховуєш загалом «релевантні» теги — ти розподіляєш їх за рівнем конкуренції/охоплення й позначаєш будь-який тег, чий реальний топ-контент, імовірно, не відповідає реальній аудиторії цього посту.

Тема/зміст посту: {{POST_TOPIC}}
Платформа: {{PLATFORM}}
Цільова аудиторія: {{TARGET_AUDIENCE}}
Наявний брендовий/спільнотний хештег, якщо є: {{BRANDED_TAG}}

Інструкції:
1. Рекомендуй 1-2 широкі, високооб'ємні теги напряму релевантні {{POST_TOPIC}} — вони максимізують охоплення, але стикаються з найбільшою конкуренцією за видимість; зазнач, що це гра на об'єм відкриття, не звідки прийде більшість якісної залученості.
2. Рекомендуй 3-5 нішевих тегів середньої конкуренції, конкретніших щодо {{POST_TOPIC}} і {{TARGET_AUDIENCE}} — тут зазвичай найкраще співвідношення охоплення до реально зацікавлених глядачів, оскільки менша конкуренція означає, що пост має кращий шанс виринути помітно в межах тегу.
3. Рекомендуй 1-2 теги, специфічні для {{BRANDED_TAG}} чи нішевого спільнотного/подієвого тегу, якщо релевантно — вони будують шукабельний архів і ідентичність спільноти з часом, навіть якщо охоплення окремого посту мале.
4. Для кожного рекомендованого тегу познач, якщо є підстави підозрювати, що він зазвичай виводить контент, не пов'язаний з {{POST_TOPIC}} (напр., тег, що тематично названий, але на практиці зсунувся означати щось інше, чи домінований непов'язаним кейсом використання) — це реальний ризик особливо з широкими однослівними тегами, і використання невідповідного тегу може притягнути покази, що не конвертуються в релевантну залученість.
5. Відкалібруй загальну кількість і стиль тегів під норми {{PLATFORM}} — конвенції хештегів і ефективні кількості суттєво різняться між платформами (напр., Instagram традиційно підтримує багато тегів, конвенції X/LinkedIn надають перевагу набагато меншій кількості), і стратегія, скопійована з однієї платформи на іншу без коригування, часто показує гірші результати.
6. Якщо {{TARGET_AUDIENCE}} — вузька чи спеціалізована група, пріоритизуй нішеві теги над широкими, навіть якщо це означає менше загальне охоплення — менша, релевантніша аудиторія, виведена нішевими тегами, зазвичай коштує більше, ніж більша, менш релевантна з широких тегів, особливо якщо {{TARGET_AUDIENCE}} сама не є масовою групою.

Формат виводу: Markdown з трьома рівнями: Широкі/Охоплюючі теги, Нішеві/Релевантні теги, Брендові/Спільнотні теги. Для кожного тегу — однорядкове обґрунтування. Явно познач будь-який тег із ризиком невідповідності релевантності.
```

## Змінні
- `{{POST_TOPIC}}` — про що реально пост. Обов'язково.
- `{{PLATFORM}}` — конкретна платформа, оскільки конвенції хештегів і ефективні кількості тегів різняться. Обов'язково.
- `{{TARGET_AUDIENCE}}` — кого цей пост намагається досягти, оскільки вибір нішевих тегів залежить від знання, хто реально рахується релевантним глядачем. Обов'язково.
- `{{BRANDED_TAG}}` — наявний брендовий чи спільнотний хештег для включення, якщо в акаунту є такий. Необов'язково.

## Приклад
**Вхід:** `{{POST_TOPIC}}` = «Туторіал з догляду за заквасковим стартером для початківців» `{{PLATFORM}}` = «Instagram» `{{TARGET_AUDIENCE}}` = «Домашні пекарі, нові саме до закваски, не загальні ентузіасти готування» `{{BRANDED_TAG}}` = «#MyStarterJourney (власний повторюваний тег акаунту)»

**Вихід (уривок):**
```
### Широкі/Охоплюючі теги
- #Sourdough — високий обсяг, напряму по темі; очікуй сильне охоплення, але важку конкуренцію за видимість у ньому.
- #BakingFromScratch — широкий, але релевантний; зазнач, що цей тег дещо змішаний із загальним контентом випічки поза хлібом, тож очікуй певне розмиття охоплення поза {{TARGET_AUDIENCE}}.

### Нішеві/Релевантні теги
- #SourdoughStarter — конкретніший за #Sourdough, імовірно виводить контент, реально релевантний для початківців, що доглядають саме за стартером.
- #SourdoughForBeginners — напряму відповідає реальному рівню навичок {{TARGET_AUDIENCE}}, краще співвідношення релевантності до охоплення, ніж широкі теги вище.
- #StarterMaintenance — достатньо нішевий, щоб конкуренція була низькою, але перевір поточний обсяг використання, перш ніж покладатись на нього — теги з дуже низьким обсягом можуть означати майже нульове відкриття, якщо тег активно не шукають.

### Брендові/Спільнотні теги
- #MyStarterJourney — будує шукабельний архів акаунту; мінімальне охоплення само по собі, але цінне для відкриття спільнотою/повторними глядачами з часом.

Позначка: топ-пости #BakingFromScratch, імовірно, включають загальний контент рецептів (не специфічний для закваски), тож попри тематичну близькість, він може притягнути глядачів, менш конкретно зацікавлених у догляді за стартером, ніж нішеві теги вище — варто моніторити якість залученості саме від цього тегу, якщо стануть доступні дані продуктивності.
```

## Поради та варіації
- Поєднуй із «Узагальнювачем звіту соціальної аналітики для зацікавлених сторін» (social-media, вже випущений) після кількох постів із заданим міксом хештегів — порівняння реальної якості залученості між тегами (не лише кількості показів) — це те, як підозрювана позначка невідповідності релевантності підтверджується чи спростовується реальними даними.
- Ефективність хештегів і конвенції платформ змінюються з часом — розглядай це як стартову стратегію для тестування й уточнення реальними даними продуктивності, не фіксовану формулу для повторного використання нескінченно без перегляду.
- Для акаунту, що часто постить на схожу тему, уникай використання точно того самого набору тегів у кожному пості — алгоритми відкриття деяких платформ знижують пріоритет контенту, що виглядає шаблонним/повторюваним, а варіювання тегів нішевого рівня між постами також перевіряє, які конкретно нішеві теги реально показують результат.
