## Опис
Рецензує схему function-calling / інструменту на предмет неоднозначності, відсутніх обмежень і небезпечних значень за замовчуванням до того, як вона потрапить у продакшн — саме схема, а не агент, зазвичай є першопричиною, коли агент постійно неправильно викликає інструмент.

## Коли використовувати
- Коли визначаєш новий інструмент для агента і хочеш перевірити схему перед тим, як її підключити.
- Коли розбираєшся, чому агент постійно неправильно використовує інструмент.
- Коли аудитуєш наявний набір визначень інструментів на консистентність.

## Промпт

```
Ти рецензуєш схему tool/function, яку AI-агент використовуватиме для виклику зовнішньої системи. Погані схеми призводять до тихого неправильного використання — розмиті назви параметрів, відсутні обмеження та недокументована поведінка при помилках є найпоширенішими першопричинами того, що агент викликає інструмент неправильно.

Схема для рецензування:
{{TOOL_SCHEMA}}

Контекст (необов'язково): {{USAGE_CONTEXT}}

Перевір її на:
1. **Неоднозначні параметри** — будь-яка назва/опис, яку модель може неправильно зрозуміти (одиниці виміру, формат, чи поле є ID чи назвою, обов'язкове воно чи ні).
2. **Відсутні обмеження** — діапазони значень, enum'и чи формати, що існують у реальності, але не закодовані (напр. поле "currency" без enum, "amount" без знака/діапазону).
3. **Недокументовану поведінку при помилках** — що відбувається при відсутньому ID, помилці прав доступу, таймауті — чи це десь описано так, щоб модель могла на це відреагувати?
4. **Небезпечні значення за замовчуванням** — будь-який параметр, який при пропуску за замовчуванням робить щось деструктивне чи дороге замість безпечної відмови.
5. **Надлишкові чи перетинні інструменти** — якщо {{USAGE_CONTEXT}} згадує інші інструменти, познач ті, які можна сплутати з цим.

Для кожної проблеми: процитуй точне поле, поясни конкретний збій, який вона уможливлює (а не просто "незрозуміло"), і дай виправлений фрагмент схеми.

Якщо в певній категорії проблем немає — прямо про це напиши. Заверши одним рядком: готово до продакшену, чи потрібна доробка — і чому.
```

## Змінні
- `{{TOOL_SCHEMA}}` — визначення інструменту/функції (JSON Schema, фрагмент OpenAPI або звичайний опис). Обов'язково.
- `{{USAGE_CONTEXT}}` — необов'язково: які інші інструменти існують поряд або як цей зазвичай викликається.

## Приклад
**Вхід:** `{{TOOL_SCHEMA}}` визначає `issue_refund(order_id: string, amount: number)` без поля валюти, без максимального значення і без документованої поведінки при помилках.

**Вихід (фрагмент):**
```
## Відсутні обмеження
- `amount` не має поля валюти чи максимального значення — агент може видати рефанд у неправильній валюті або на необмежену суму.
  Виправлення: додай `currency: enum [USD, EUR, ...]` та `amount: number, maximum: <сума замовлення>`.

**Висновок:** Потрібна доробка — необмежений `amount` це реальний фінансовий ризик.
```

## Поради та варіації
- Для MCP-визначень інструментів окремо перевір, чи достатньо самого поля `description` (без зовнішньої документації), щоб модель використовувала інструмент правильно.
- Для систем із багатьма інструментами прогони цей промпт для кожного інструменту окремо, а потім зроби окремий прохід, порівнюючи всі описи інструментів попарно на предмет перетину.
