## Опис
Оцінює розмір вибірки, потрібний для надійного виявлення заданого розміру ефекту до запуску тесту, або розмір ефекту, який реально здатна виявити наявна вибірка — планувальний аналог уже випущеного «Селектора статистичних тестів», який використовується до збору даних, а не після нього.

## Коли використовувати
- Перед запуском A/B-тесту чи експерименту, щоб знати, скільки користувачів чи спостережень потрібно, перш ніж результату «немає значущої різниці» можна буде довіряти.
- Коли зацікавлені сторони пропонують фіксовану тривалість тесту чи розподіл трафіку, і хочеш знати, який розмір ефекту цей план реально здатен виявити.
- Ретроспективний перегляд завершеного експерименту, щоб перевірити, чи він взагалі мав достатню потужність для виявлення ефекту, на який розраховувала команда.

## Промпт

```
Ти статистичний радник, що допомагає спланувати розмір вибірки перед запуском тесту, а не аналізує вже завершений тест.

Що тестується і тип метрики (напр., «конверсія, бінарна» або «середня вартість замовлення, безперервна»): {{METRIC_TYPE}}
Базове значення і варіативність, якщо відомі (напр., базова конверсія 4%, або середнє/стандартне відхилення для безперервної метрики): {{BASELINE}}
Мінімальний розмір ефекту, який варто виявити — найменша зміна, що справді вплинула б на рішення (напр., «відносний приріст 10%» або «збільшення середньої вартості замовлення на $2»): {{MINIMUM_EFFECT}}
Бажаний рівень значущості і потужність, якщо відомі (за замовчуванням alpha=0.05, потужність=0.80, якщо не вказано): {{SIG_AND_POWER}}
Відома обмеженість, якщо є (фіксований доступний трафік чи часове вікно, або «немає»): {{CONSTRAINT}}

Зроби наступне:
1. Вкажи, яке стандартне сімейство тестів застосовується, зважаючи на {{METRIC_TYPE}} (напр., z-тест для двох пропорцій для бінарної метрики конверсії, t-тест для двох вибірок для безперервної метрики), і чому.
2. Використовуючи {{BASELINE}}, {{MINIMUM_EFFECT}} та {{SIG_AND_POWER}}, розрахуй потрібний розмір вибірки на групу. Явно покажи вхідні дані розрахунку (а не лише кінцеве число), щоб його можна було перевірити чи перерахувати.
3. Якщо {{CONSTRAINT}} обмежує досяжну вибірку нижче того, що вимагає крок 2, розрахуй натомість мінімальний розмір ефекту, який ця обмеженість реально здатна виявити при бажаній потужності, щоб той, хто запитує, знав, що насправді тестується за такого рівня трафіку.
4. Явно познач, якщо {{MINIMUM_EFFECT}} вказано як відносну зміну відносно малого {{BASELINE}} (напр., приріст 10% на базовому значенні 0.5%) — малі відносні прирости на малих базових значеннях вимагають непропорційно великих вибірок, і це поширена помилка планування, яку варто явно висвітлити, а не мовчки прорахувати повз неї.
5. Вкажи одне застереження звичайною мовою: ця оцінка припускає, що реальна варіативність метрики відповідає тому, що вказує чи мається на увазі в {{BASELINE}} — якщо фактична дисперсія під час тесту виявиться вищою (поширено для скошених метрик на кшталт доходу), справжній потрібний розмір вибірки більший за цю оцінку.

Формат виводу: Markdown з підписаними секціями: Тип тесту, Потрібний розмір вибірки (з показаним розрахунком), Вплив обмеженості (лише якщо {{CONSTRAINT}} не «немає»), Застереження.
```

## Змінні
- `{{METRIC_TYPE}}` — що тестується і чи метрика бінарна, чи безперервна. Обов'язково — визначає сімейство тесту і формулу.
- `{{BASELINE}}` — поточне значення і варіативність метрики. Обов'язково — основний вхід розрахунку розміру вибірки.
- `{{MINIMUM_EFFECT}}` — найменша зміна, яку варто виявити. Обов'язково — без цього питання «скільки вибірки мені потрібно» не має визначеної відповіді.
- `{{SIG_AND_POWER}}` — бажані alpha/потужність, або порожньо для використання значення за замовчуванням 0.05/0.80.
- `{{CONSTRAINT}}` — жорстка межа доступної вибірки, або «немає».

## Приклад
**Вхід:** `{{METRIC_TYPE}}` = «Конверсія оформлення замовлення, бінарна.» `{{BASELINE}}` = «Поточна конверсія: 4%.» `{{MINIMUM_EFFECT}}` = «Відносний приріст 10% (4% → 4.4%).» `{{SIG_AND_POWER}}` = «за замовчуванням» `{{CONSTRAINT}}` = «немає»

**Вихід (уривок):**
```
### Тип тесту
z-тест для двох пропорцій — {{METRIC_TYPE}} є бінарною метрикою конверсії, що порівнює дві пропорції (контроль проти лікування).

### Потрібний розмір вибірки
p1 = 0.04, p2 = 0.044, різниця = 0.004. Об'єднаний член дисперсії ≈ p1(1-p1) + p2(1-p2) = 0.0384 + 0.0421 = 0.0805. При alpha=0.05 (z=1.96) і потужності=0.80 (z=0.84): n ≈ (1.96+0.84)² × 0.0805 / 0.004² ≈ 7.84 × 0.0805 / 0.000016 ≈ **39 400 на групу** (~78 800 загалом).

### Застереження
- Це відносний приріст 10% на й так малому базовому значенні 4% — саме тому потрібна вибірка настільки велика; відносний приріст 10% на базовому значенні 40% потребував би приблизно в 10 разів менше спостережень. Переконайся, що це справді найменший приріст, який варто виявити, перш ніж закладатись на такий розмір вибірки.
- Припускає, що дисперсія конверсії точно відповідає заявленому базовому значенню; якщо фактична дисперсія вища, справжня потрібна вибірка більша за 39 400/групу.
```

## Поради та варіації
- Поєднуй напряму з «Селектором статистичних тестів» (data-and-analysis, вже випущений): спочатку запусти цей промпт, щоб спланувати розмір вибірки, а потім той, коли дані вже зібрані, щоб підтвердити, що застосовується правильний тест, зважаючи на фактичну форму даних.
- Якщо {{CONSTRAINT}} змушує використати меншу вибірку, ніж потрібно, не приймай мовчки слабший результат «Впливу обмеженості» — передай його тому, хто відповідає за рішення, яке має інформувати тест, оскільки тест, здатний виявити лише великі ефекти, може бути взагалі невартим запуску для рішення, що залежить від малого.
- Для метрики з довгим хвостом (дохід, тривалість сесії) явно зазнач це в {{BASELINE}}, а не лише вкажи середнє/стандартне відхилення — скошені розподіли часто потребують більшої вибірки, ніж припускає формула нормального наближення в цьому промпті, і крок застережень позначить це точніше, якщо йому про це сказати.
