## Опис
Складає зрозумілий людині словник даних — по одному запису на колонку зі звичайним описом, виведеним доменом значень і позначеними застереженнями — зі схеми таблиці плюс невеликого зразка реальних рядків, для документування таблиці, на яку ніхто не написав документацію.

## Коли використовувати
- Успадкував(-ла) таблицю бази даних чи звітну вʼю без документації і потрібне швидке, зрозуміле довідкове джерело, перш ніж будувати щось поверх неї.
- Онбордиш нового аналітика чи інженера на набір даних і хочеш початковий словник даних, який вони скоріше виправлять, ніж писатимуть з нуля.
- Перед тим як відкрити таблицю для BI-інструмента чи зовнішніх споживачів, і хочеш первинний опис кожної колонки для перегляду й уточнення.

## Промпт

```
Ти складаєш зрозумілий людині словник даних для таблиці бази даних, маючи її схему та невеликий зразок реальних рядків.

Назва таблиці та схема (назви колонок, типи та будь-які заявлені обмеження): {{SCHEMA}}
Зразкові рядки (кілька реальних чи репрезентативних рядків): {{SAMPLE_ROWS}}
Відомий бізнес-контекст, якщо є (для чого таблиця, хто нею володіє): {{CONTEXT}}

Для кожної колонки в {{SCHEMA}} створи:
1. Опис у одне речення звичайною мовою того, що представляє колонка, виведений з її назви, типу та значень, побачених у {{SAMPLE_ROWS}} — пиши це для читача, незнайомого з таблицею, а не як переказ назви колонки.
2. Її видимий домен значень із {{SAMPLE_ROWS}} (напр., спостережувані значення переліку, числовий діапазон, поле вільного тексту) — вкажи «недостатньо зразка для визначення», а не вгадуй, якщо {{SAMPLE_ROWS}} не показує достатньої варіативності.
3. Позначене застереження, якщо щось у {{SAMPLE_ROWS}} виглядає несумісним із заявленим типом/обмеженням колонки (напр., колонка, що допускає null, без жодного null у зразку — зазнач, що це може бути просто через розмір зразка, а не гарантія; чи колонка, «схожа на булеву», що зберігається як рядок із непослідовним регістром).
4. Чи виглядає колонка первинним ключем, зовнішнім ключем, чи похідним/обчислюваним значенням, якщо це можна вивести з конвенції найменування чи {{CONTEXT}} — познач це як припущення, а не підтверджений факт, якщо {{SCHEMA}} не заявляє це явно.

Після словника по колонках додай короткий розділ «Відкриті питання» з переліком того, що людина-рецензент має підтвердити, перш ніж довіряти цьому словнику (напр., неоднозначні назви колонок, видимі несумісності, відсутній {{CONTEXT}}).

Формат виводу: Markdown-таблиця з колонками: Колонка, Опис, Домен значень, Застереження, Тип ключа (виведено). Далі — список відкритих питань.
```

## Змінні
- `{{SCHEMA}}` — назва таблиці, назви колонок, типи та обмеження. Обов'язково.
- `{{SAMPLE_ROWS}}` — кілька реальних чи репрезентативних рядків. Обов'язково — це основний доказ для описів і застережень; без нього словник — це здогадки лише з назв.
- `{{CONTEXT}}` — бізнес-контекст/володіння. Необов'язково, але покращує якість описів і виведення типу ключа.

## Приклад
**Вхід:** `{{SCHEMA}}` = «Таблиця: orders. Колонки: order_id (uuid, not null), customer_id (uuid, not null), status (varchar(20), not null), total_cents (integer, not null), created_at (timestamp, not null), refunded_at (timestamp, nullable).» `{{SAMPLE_ROWS}}` = «3 рядки: побачені значення status = 'pending', 'shipped', 'refunded'; total_cents у діапазоні 999-45000; refunded_at — null у 2 з 3 рядків, заповнено в рядку зі статусом 'refunded'.» `{{CONTEXT}}` = «Належить команді orders; живить фінансовий дашборд доходу.»

**Вихід (уривок):**
```
| Колонка | Опис | Домен значень | Застереження | Тип ключа (виведено) |
|---|---|---|---|---|
| order_id | Унікальний ідентифікатор одного замовлення клієнта. | UUID, унікальний для кожного рядка (виведено з назви, безпосередньо не підтверджувано на зразку з 3 рядків). | Не виявлено. | Первинний ключ (виведено з назви + not-null + конвенції унікальності). |
| customer_id | Ідентифікує, який клієнт зробив замовлення. | UUID. | Не виявлено. | Зовнішній ключ до таблиці customers (виведено — не заявлено в схемі). |
| status | Поточний стан життєвого циклу замовлення. | Спостережено: pending, shipped, refunded. Недостатньо зразка, щоб підтвердити, що це повний перелік — ймовірно, включає й стани на кшталт «cancelled» чи «delivered», не побачені в цих 3 рядках. | Не виявлено, окрім обмеження розміру зразка. | Не ключ. |
| total_cents | Сума замовлення в центах (мінімальна одиниця валюти). | Спостережений діапазон: 999-45000 (тобто $9.99-$450.00). | Назва колонки натякає на центи, а не долари — підтверди, що ця конвенція витримується послідовно, перш ніж використовувати у фінансовому дашборді. | Не ключ. |
| refunded_at | Часова мітка повернення коштів за замовлення, якщо застосовно. | Null для неповернутих замовлень; заповнено для рядка зі статусом 'refunded' у зразку. | Корелює зі status = 'refunded' у цьому зразку — варто підтвердити, що це забезпечується (напр., обмеженням чи логікою застосунку), а не збіг. | Не ключ. |

### Відкриті питання
- Чи конвенція найменування «cents» у total_cents послідовна для всіх грошових колонок у цій схемі, чи специфічна для цієї таблиці?
- Чи має status фіксоване обмеження-перелік на рівні бази даних, чи «pending/shipped/refunded» — це просто те, що з'явилось у цьому малому зразку?
- Підтверди цільову таблицю зовнішнього ключа customer_id з командою orders, оскільки {{SCHEMA}} не заявляє це явно.
```

## Поради та варіації
- Поєднуй з «Аудитором визначень метрик дашборду» (data-and-analysis, вже випущений) щойно поверх цієї таблиці почнуть будувати метрики — той промпт ловить неоднозначні визначення *метрик*, тоді як цей документує базові *колонки*, з яких ці метрики обчислюються.
- Чим більше рядків надано в {{SAMPLE_ROWS}}, тим надійніші розділи домену значень і застережень — зразок із 3 рядків (як у прикладі) достатній, щоб продемонструвати формат, але його варто розглядати як чернетку для перевірки на більшому експорті, перш ніж повністю довіряти.
- Якщо {{SCHEMA}} містить колонки, які цей промпт не може впевнено інтерпретувати навіть зі зразком (напр., непрозору колонку з JSON-блобом), цілком нормально, щоб словник відверто це вказав, а не вигадував правдоподібний опис.
