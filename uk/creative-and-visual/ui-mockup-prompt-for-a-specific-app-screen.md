## Опис
Складає промпт для генерації зображення макета UI конкретного екрана застосунку — для раннього візуального дослідження й настрою/напрямку, не для готового до продакшену UI (згенеровані макети UI — для натхнення й комунікації зі стейкхолдерами, не піксель-точні, реалізовувані інтерфейси).

## Коли використовувати
- Ти на етапі раннього концептуального дослідження візуального напрямку застосунку й хочеш швидку макетну графіку, щоб на неї відреагувати, перш ніж інвестувати в роботу в реальному дизайн-інструменті.
- Хочеш повідомити візуальний настрій/напрямок стилю дизайнеру чи стейкхолдеру («щось на кшталт цього»), а не буквальну специфікацію.
- Потрібна плейсхолдерна графіка UI для пітч-деку чи маркетингового макета, що показує «застосунок», без потреби в реально функціонуючому файлі дизайну.

## Промпт

```
Mobile app UI design mockup, {{SCREEN_TYPE}} screen, {{APP_CATEGORY}} app, {{DESIGN_STYLE}} design style, {{COLOR_SCHEME}} color scheme, showing {{KEY_ELEMENTS}}, clean modern interface, {{DEVICE_FRAME}}, UI/UX design, high fidelity mockup, Figma-style presentation --ar {{ASPECT_RATIO}}
```

## Змінні
- `{{SCREEN_TYPE}}` — конкретний екран (напр., «онбординг», «дашборд/головна», «налаштування», «флоу оформлення замовлення»). Обов'язково.
- `{{APP_CATEGORY}}` — домен застосунку (напр., «трекінг фітнесу», «доставка їжі», «особисті фінанси»). Обов'язково — спрямовує доречну іконографію й конвенції контенту.
- `{{DESIGN_STYLE}}` — напр., «мінімалістичний плоский дизайн», «неоморфізм», «гласморфізм із глибиною», «яскравий і кольоровий, орієнтований на Gen-Z». Обов'язково — розпливчасті терміни стилю дають загальні, невиразні результати.
- `{{COLOR_SCHEME}}` — конкретні кольори чи описана палітра (напр., «глибокий темно-синій і теплий кораловий акцент», «монохром з одним яскраво-зеленим акцентом»). Обов'язково.
- `{{KEY_ELEMENTS}}` — конкретні елементи UI, що мають бути видимими (напр., «нижня навігаційна панель, велика hero-картка, три статистичні віджети»). Обов'язково — без цього модель вигадує загальні елементи UI, що можуть не відображати реальний продуктовий концепт.
- `{{DEVICE_FRAME}}` — напр., «показано в рамці iPhone», «показано як плоский екран без обрамлення пристрою». Обов'язково — впливає на композицію й те, як зображення можна використати.
- `{{ASPECT_RATIO}}` — узгоджено з рамкою пристрою, якщо використовується (напр., «9:19.5» для сучасного екрана телефону), чи зручне для презентації співвідношення, якщо без рамки.

## Приклад
**Вхід:** `{{SCREEN_TYPE}}` = «дашборд/головна» · `{{APP_CATEGORY}}` = «особисті фінанси / бюджетування» · `{{DESIGN_STYLE}}` = «мінімалістичний плоский дизайн з м'якими заокругленими картками» · `{{COLOR_SCHEME}}` = «глибокий темно-синій фон, м'ятний зелений акцент, білі картки» · `{{KEY_ELEMENTS}}` = «велика картка підсумку балансу зверху, діаграма розподілу витрат, горизонтальний прокручуваний список останніх транзакцій, нижня панель вкладок» · `{{DEVICE_FRAME}}` = «показано в рамці сучасного iPhone» · `{{ASPECT_RATIO}}` = «9:19.5»

**Заповнений промпт:**
```
Mobile app UI design mockup, dashboard/home screen, personal finance / budgeting app, minimalist flat design with soft rounded cards design style, deep navy background with mint green accent and white cards color scheme, showing a large balance summary card at top, a spending breakdown chart, a horizontal scrollable list of recent transactions, a bottom tab bar, clean modern interface, shown in a modern iPhone frame, UI/UX design, high fidelity mockup, Figma-style presentation --ar 9:19.5
```

## Поради та варіації
- Трактуй будь-який згенерований макет як референс настрою/напрямку, не дизайн-результат — текстові підписи, іконки й точний spacing не будуть надійно читабельними чи правильними, і жоден згенерований макет не варто передавати інженерії як специфікацію реалізації.
- Для дослідження кількох напрямків стилю того самого екрана тримай {{SCREEN_TYPE}}, {{APP_CATEGORY}} і {{KEY_ELEMENTS}} ідентичними між генераціями й варіюй лише {{DESIGN_STYLE}} і {{COLOR_SCHEME}} — це ізолює стиль як реальну змінну, що порівнюється, та сама дисципліна, що «consistent-character-sheet-prompt-series» (creative-and-visual) застосовує до роботи з персонажами.
- Коли напрямок затверджено, передай виграшний приклад (не сам промпт) дизайнеру, що працює в реальному дизайн-інструменті — згенероване зображення — референс для перекладу в реальний, редагований, доступний інтерфейс, не заміна цієї роботи.
