## Опис
Сканує скрипт на слова, які TTS-рушій імовірно вимовить неправильно — власні назви, абревіатури, галузевий жаргон і гетероніми (слова, написані однаково, але вимовлені по-різному залежно від значення) — і генерує фонетичне переписання чи пропозиції SSML-фонем для кожного, замість того щоб покладатись на прослуховування поганого рендерингу постфактум.

## Коли використовувати
- Ось-ось запустиш скрипт через TTS-пайплайн і хочеш зловити ймовірні помилки вимови перед генерацією аудіо, а не після оплати генерації й виявлення помилок.
- Вивід TTS неправильно вимовив конкретні слова, і потрібні системні виправлення (не лише для вже виявлених слів, а й для подібних слів деінде в скрипті, що провалились би так само).
- Локалізуєш чи повторно використовуєш скрипт між TTS-рушіями/голосами і хочеш підтвердити, що слова з ризиком вимови позначені послідовно, оскільки різні рушії обробляють те саме складне слово по-різному.

## Промпт

```
Ти сканєш скрипт на слова, які TTS-рушій імовірно вимовить неправильно, і генеруєш виправлення для кожного.

Скрипт: {{SCRIPT}}
Платформа/рушій TTS, якщо відомо (впливає на доступний синтаксис виправлення): {{TTS_PLATFORM}}
Галузеві терміни, вже відомі як складні, якщо є: {{KNOWN_RISKY_TERMS}}

Інструкції:
1. Скануй на власні назви (імена, бренди, місця), що не є звичайними словниковими словами — це найпоширеніше джерело неправильної вимови TTS, оскільки рушій не має надійної вимови, на яку спертись.
2. Скануй на абревіатури й ініціалізми та визнач для кожної, чи вона має читатись по буквах, чи як слово (акронім, вимовлений як одне слово) — познач будь-яку, яку TTS-рушій міг би вимовити неправильно за замовчуванням (напр., читання «NASA» по буквах, чи читання абревіатури, яка має бути по буквах, ніби вона слово).
3. Скануй на гетероніми — слова, написані ідентично, але вимовлені по-різному за значенням — познач кожен випадок із тим, яка вимова контекст реально вимагає, оскільки TTS-рушій часто вгадує неправильно без контексту, що усуває неоднозначність.
4. Скануй на галузевий жаргон чи технічні терміни, малоймовірні в загальному словнику вимови TTS, плюс усе в {{KNOWN_RISKY_TERMS}}.
5. Для кожного позначеного терміна надай фонетичне переписання простою, читабельною формою (напр., «Xiomara» → «сі-о-МА-ра») І, якщо {{TTS_PLATFORM}} відома й підтримує це, доречну для платформи розмітку (напр., тег SSML `<phoneme>` з IPA чи специфічним для платформи алфавітом) — надай просте переписання незалежно від платформи, оскільки це корисно навіть без підтримки розмітки.
6. Не позначай звичайні слова зі стандартною, однозначною вимовою лише щоб виглядати ретельним — довгий список непотрібних позначок такий самий некорисний, як пропущені реальні ризики, оскільки він ховає слова, що реально потребують уваги.

Формат виводу: таблиця Markdown зі стовпцями: Термін | Тип ризику (власна назва / абревіатура / гетеронім / жаргон) | Контекст правильної вимови | Фонетичне переписання | Розмітка платформи (якщо застосовно). Заверши кількістю позначених термінів і однорядковою приміткою, якщо {{TTS_PLATFORM}} не вказана (обмежує корисність розмітки).
```

## Змінні
- `{{SCRIPT}}` — текст скрипту для сканування. Обов'язково.
- `{{TTS_PLATFORM}}` — конкретний TTS-рушій/платформа, якщо відомо, оскільки синтаксис розмітки фонем різниться між рушіями. Необов'язково — просте фонетичне переписання все одно генерується без нього.
- `{{KNOWN_RISKY_TERMS}}` — будь-які терміни, вже відомі як проблемні з минулого досвіду з цим скриптом чи подібним. Необов'язково, але гарантує, що вони явно покриті, а не покладаються лише на сканування, щоб їх зловити.

## Приклад
**Вхід:** `{{SCRIPT}}` = «Наш CEO, Siobhan Ó Riain, представить результати Q3. Будь ласка, прочитай звіт перед зустріччю — це швидке читання.» `{{TTS_PLATFORM}}` = «Amazon Polly» `{{KNOWN_RISKY_TERMS}}` = «не надано»

**Вихід (уривок):**
```
| Термін | Тип ризику | Контекст правильної вимови | Фонетичне переписання | Розмітка платформи |
|---|---|---|---|---|
| Siobhan Ó Riain | Власна назва | Ірландське ім'я, неочевидне зіставлення написання-звучання | «шив-ОН о РІ-ан» | `<phoneme alphabet="ipa" ph="ʃɪˈvɔːn oʊ ˈriːən">Siobhan Ó Riain</phoneme>` |
| Q3 | Схоже на абревіатуру | Читається як «к'ю-три» (буква + число), не повністю по буквах і не помилково як слово | «к'ю ТРИ» | `<say-as interpret-as="characters">Q3</say-as>` |

2 терміни позначено.
```

## Поради та варіації
- Поєднуй із «Скриптом озвучки з анотаціями напрямку подачі» (voice-and-audio, вже випущений) — той промпт анотує темп/тон/наголос; цей конкретно сфокусований на правильності вимови, інший і взаємодоповнюючий шар підготовки скрипту перед записом чи TTS-генерацією.
- Якщо той самий скрипт буде запущено через кілька TTS-рушіїв чи голосів, повторно запускай цю перевірку на кожну платформу, коли {{TTS_PLATFORM}} змінюється — синтаксис розмітки й словники вимови за замовчуванням достатньо різняться між рушіями, тож виправлення, підтверджене на одній платформі, може не перенестись напряму на іншу.
- Для скрипту, що повторно використовується (вічнозелена реклама, повторюване інтро), зберігай список виправлень поряд із самим скриптом, щоб майбутні редагування можна було перевіряти проти відомо складних термінів без повторного сканування з нуля щоразу.
