## Опис
Діагностує, чому макет ламається на конкретних розмірах екрана — переповнення, перенесення, накладання — з фактичного CSS/розмітки та опису симптому, а не загальне пояснення "як працює адаптивний дизайн". Для конкретного, відтворюваного бага макета.

## Коли використовувати
- Макет виглядає добре на десктопі, але ламається (переповнюється, елементи накладаються, текст погано переноситься) на конкретній ширині viewport.
- Дебаг проблеми макета, яку описав лише звіт QA чи скріншот з конкретного пристрою, без прямого доступу для відтворення.
- Навчання систематичного читання багів CSS-макета замість випадкового підбору ширин, доки щось не виглядатиме правильно.

## Промпт

```
Ти діагностуєш баг адаптивного макета з коду й опису симптому — не загальний туторіал з адаптивного дизайну.

HTML/JSX і відповідний CSS: {{CODE}}
Симптом (що ламається, і на якій ширині viewport/пристрої): {{SYMPTOM}}
Опис скріншота, якщо зображення недоступне (необов'язково): {{VISUAL_DESCRIPTION}}

Інструкції:
1. Визнач конкретний механізм CSS, що спричиняє симптом: фіксовану ширину/min-width, що не стискається, елемент flex/grid без дозволу на стиснення/перенесення, зображення без обмеження max-width, медіазапит з помилкою на одиницю в межі breakpoint'а, контент (на кшталт довгого нерозривного рядка/URL), що не переноситься, чи батьківський елемент з `overflow: hidden`, що маскує глибшу проблему.
2. Простеж алгоритм макета, що використовується (flexbox, grid чи звичайний потік), і міркуй про нього коректно — flexbox і grid мають різну поведінку за замовчуванням для стиснення/розтягування, яку часто неправильно розуміють, тож будь точним щодо того, що застосовується тут.
3. Якщо кілька правил CSS могли б правдоподібно взаємодіяти, спричиняючи симптом (напр., flex-basis, що конфліктує з min-width), простеж через каскад і обчислені значення, а не вгадуй одну причину.
4. Дай конкретне виправлення: точну зміну властивості/значення CSS, не "зроби адаптивним". Якщо є кілька валідних виправлень (напр., `flex-shrink`, `min-width: 0`, чи `overflow-wrap`), обери те, що адресує першопричину, а не маскує симптом, і скажи чому.
5. Зазнач, чи виправлення може мати побічні ефекти на інших ширинах viewport (виправлення для мобільного, що змінює поведінку на десктопі), і скажи, що перевірити після застосування.
6. Якщо опис симптому занадто розпливчастий для впевненого діагнозу (напр., "на мобільному виглядає дивно"), запитай конкретний breakpoint і що означає "дивно" (переповнення? накладання? неправильний порядок?), замість того щоб вгадувати.

Формат виводу: Markdown з розділами: Першопричина, Виправлення (з кодом), Побічні ефекти для перевірки.
```

## Змінні
- `{{CODE}}` — відповідний HTML/JSX і CSS. Обов'язково.
- `{{SYMPTOM}}` — що ламається і на якому розмірі viewport. Обов'язково.
- `{{VISUAL_DESCRIPTION}}` — опис того, що візуально не так, якщо скріншот недоступний для поширення. Необов'язково, але допомагає, коли самого коду недостатньо, щоб зробити баг очевидним.

## Приклад
**Вхід:** `{{CODE}}` = flex-рядок, що містить бічну панель фіксованої ширини і текстовий блок, `{{SYMPTOM}}` = "на екранах менше 400px довгі слова текстового блоку переповнюють край контейнера замість перенесення".

**Вихід (фрагмент):**
```
## Першопричина
Текстовий блок є flex-елементом без `min-width: 0`. Flex-елементи за замовчуванням мають `min-width: auto`, що означає, що flex-елемент не стиснеться менше за внутрішній мінімальний розмір свого контенту — для тексту з довгим нерозривним словом/URL цей мінімум може перевищити доступний простір, спричиняючи переповнення замість перенесення.

## Виправлення
```css
.text-block {
  min-width: 0;
  overflow-wrap: break-word;
}
```
`min-width: 0` дозволяє flex-елементу стискатися нижче природного мінімуму свого контенту; `overflow-wrap: break-word` гарантує, що будь-який залишковий довгий нерозривний контент переноситься замість переповнення.

## Побічні ефекти для перевірки
Підтверди, що текстовий блок не стає незручно вузьким на проміжних ширинах тепер, коли він може стискатися сильніше, ніж раніше — перевір конкретно 400-600px.
```

## Поради та варіації
- Якщо маєш доступ до DevTools браузера, встав фактичні обчислені значення стилю для зламаного елемента на ширині viewport, де він падає — це перетворює діагноз з висновку на підтвердження.
- Для макета CSS Grid замість flexbox та сама пастка "min-width: auto за замовчуванням" існує як `minmax(auto, ...)` — попроси перевірити grid-специфічну версію цієї проблеми, якщо використовується grid.
