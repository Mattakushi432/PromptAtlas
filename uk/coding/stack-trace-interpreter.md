## Опис
Перетворює сирий стек-трейс чи повідомлення про помилку на пояснення простою мовою того, що насправді сталося, та ранжований список імовірних першопричин — для будь-кого, від новачка, збентеженого стіною тексту, до senior-інженера, який швидко проводить триаж.

## Коли використовувати
- Зустрів незнайомий тип помилки/винятку і хочеш зрозуміти його перед зануренням у код.
- Триаж звіту про помилку від користувача чи агрегатора логів з обмеженим контекстом навколо.
- Навчання молодшого інженера дійсно читати стек-трейс, а не просто вставляти його в пошуковик.

## Промпт

```
Ти пояснюєш помилку розробнику, який хоче її зрозуміти, а не просто отримати вставлене виправлення.

Стек-трейс / повідомлення про помилку:
{{ERROR_MESSAGE}}

Відповідний код (необов'язково, якщо маєш файл(и), на які вказує трейс):
{{RELEVANT_CODE}}

Мова/рантайм: {{LANGUAGE_OR_RUNTIME}}

Інструкції:
1. Простою мовою поясни, що цей тип помилки означає загалом (напр., "NullPointerException означає, що код спробував викликати метод на посиланні, якому ніколи не було присвоєно об'єкт").
2. Пройдися по стек-трейсу від верхнього фрейму вниз, пояснюючи, що робив кожен релевантний фрейм у момент помилки — пропускай шумні фрейми фреймворків/бібліотек, якщо вони не інформативні, але скажи, що пропускаєш їх.
3. Перелічи найімовірніші першопричини, ранжовані за ймовірністю з урахуванням трейсу та наданого коду — не просто "верхній фрейм і є проблемою", бо справжня причина часто на кілька фреймів вище.
4. Для кожної ймовірної причини вкажи, які докази в трейсі/коді її підтверджують і що варто перевірити, щоб підтвердити чи виключити її.
5. Якщо трейс обрізаний, спотворений або в ньому бракує ключових фреймів — скажи, чого бракує і яка додаткова інформація (повний трейс, код навколо, вхідні дані, що спричинили помилку) дозволила б звузити пошук — не вгадуй із хибною впевненістю.
6. Дай один-два конкретні наступні кроки (конкретний лог для перевірки, точку зупину для встановлення, значення для виводу) — не загальне "перевір свою логіку".

Формат виводу: Markdown із заголовками: Що означає ця помилка, Розбір трейсу, Імовірні причини (ранжовано), Наступні кроки.
```

## Змінні
- `{{ERROR_MESSAGE}}` — текст стек-трейсу чи помилки, якомога повніший. Обов'язково.
- `{{LANGUAGE_OR_RUNTIME}}` — напр. "Python 3.12", "Node.js 20", "Java 21 / Spring". Обов'язково — формат трейсу та типові причини різняться за рантаймом.
- `{{RELEVANT_CODE}}` — вихідний код файлу(ів)/функції(й), названих у трейсі. Необов'язково, але суттєво підвищує точність.

## Приклад
**Вхід:** `{{LANGUAGE_OR_RUNTIME}}` = "Node.js", `{{ERROR_MESSAGE}}` = `TypeError: Cannot read properties of undefined (reading 'id')` у `getUserName (user.js:14)`.

**Вихід (фрагмент):**
```
## Що означає ця помилка
`TypeError: Cannot read properties of undefined` означає, що код звернувся до властивості (`.id`) значення, яке виявилося `undefined`, а не очікуваним об'єктом.

## Імовірні причини (ранжовано)
1. **Найімовірніше:** `getUserName` викликається з аргументом `user`, що є `undefined` — напр., вищерозташований пошук (запит до БД, виклик API) повернув порожній результат, і це не було перевірено перед передачею.
2. Менш імовірно: об'єкт існує, але його поле `.id` дійсно відсутнє через зміну схеми даних.

## Наступні кроки
- Залогуй значення `user` прямо перед його передачею в `getUserName` у місці виклику.
- Перевір, чи має вищерозташований пошук шлях обробки помилки/відсутності результату, який зараз не обробляється.
```

## Поради та варіації
- Для аудиторії новачків попроси додати абзац-вступ "як загалом читати стек-трейс" перед конкретним аналізом.
- Встав кілька трейсів з одного інциденту разом і попроси визначити, чи мають вони спільну першопричину — корисно для триажу сплеску схожих помилок.
