## Опис
Перевіряє AI-згенерований код конкретно на режими відмов, характерні для AI-генерації — галюциновані API/бібліотеки, тонко неправильна логіка, що читається правдоподібно, мовчки пропущені крайові випадки, непотрібна складність — не загальне код-рев'ю. Для коду, виробленого AI-кодинг інструментом, який потребує скептичного другого проходу перед тим, як йому довіряти.

## Коли використовувати
- AI-кодинг агент видав нетривіальний шматок коду, і ти хочеш систематичний прохід на AI-специфічні режими відмов перед мерджем, не просто загальне рев'ю.
- Рев'ю PR, де ти підозрюєш (чи знаєш), що значні частини AI-згенеровані, і хочеш відповідно відкалібрувати ретельність.
- Побудова звички критично перевіряти вивід AI, а не приймати впевнено звучний код за чисту монету.

## Промпт

```
Ти рецензуєш AI-згенерований код конкретно на режими відмов, характерні для AI-генерації коду — не загальне код-рев'ю, що покриває все, що покрило б рев'ю PR, написаного людиною.

AI-згенерований код: {{CODE}}
Мова/стек: {{LANGUAGE_OR_STACK}}
Що він мав робити (оригінальний запит/завдання, якщо доступний): {{ORIGINAL_TASK}}

Інструкції:
1. Перевір на галюциновані API: чи код викликає функцію, метод чи фічу бібліотеки, що насправді не існує в заявленій бібліотеці/версії, чи існує, але з іншою сигнатурою, ніж використана? Це найхарактерніший режим відмови AI — познач усе, у чому ти не повністю впевнений, що воно реальне, навіть якщо виглядає правдоподібно, а не припускай, що знайомість означає коректність.
2. Перевір на тонко неправильну логіку, що читається впевнено й чисто: AI-згенерований код часто має хороший стиль і чітке іменування навіть коли базова логіка неправильна, що ускладнює виявлення багів побіжним переглядом — простеж фактичну логіку проти {{ORIGINAL_TASK}}, а не довіряй, що чистий код — це коректний код.
3. Перевір на мовчки пропущені крайові випадки: чи код добре обробляє заявлений happy path, але мовчки пропускає обробку помилок, обробку порожнього вводу чи випадок, на який оригінальний запит натякав, але явно не сформулював? Вивід AI часто оптимізується під чітко заявлений випадок і недообробляє неявні.
4. Перевір на непотрібну складність чи розповзання обсягу: чи AI вирішив ширшу чи "вражаючу" версію проблеми, ніж просили, вводячи абстракцію, опції конфігурації чи узагальненість, яку не запитували і яка додає навантаження на підтримку без відповідної вигоди?
5. Перевір на застарілі патерни: чи код використовує застаріле API, старий ідіом чи патерн, що був правильним колись, але відтоді витіснений, відображаючи застарілі дані навчання, а не поточну найкращу практику для цієї версії бібліотеки/мови?
6. Перевір на сфабриковано звучну впевненість у коментарях: чи коментар стверджує щось про поведінку, продуктивність чи коректність, що насправді не перевірено/неперевірне з самого коду — AI-згенеровані коментарі можуть звучати авторитетно, будучи спекулятивними чи неправильними.
7. Розрізняй знахідки з ВИСОКОЮ впевненістю (конкретний виклик API, який ти можеш перевірити, що не існує, чи логіка, демонстративно неправильна для заданого вводу) від того, що варте подвійної перевірки, але не точне — не подавай невпевнені знахідки з хибною впевненістю, оскільки весь сенс цього рев'ю — доречний скептицизм, не параноя.

Формат виводу: Markdown, один запис на знахідку, згруповано за категорією (Галюциновані API / Помилки логіки / Пропущені крайові випадки / Непотрібна складність / Застарілі патерни / Надто впевнені коментарі), кожен з рівнем впевненості і конкретним виправленням чи кроком перевірки.
```

## Змінні
- `{{CODE}}` — AI-згенерований код для рецензування. Обов'язково.
- `{{LANGUAGE_OR_STACK}}` — мова/бібліотека/версія, потрібна для точної перевірки існування API. Обов'язково.
- `{{ORIGINAL_TASK}}` — що код мав досягти. Необов'язково, але різко покращує перевірки коректності логіки й розповзання обсягу.

## Приклад
**Вхід:** `{{LANGUAGE_OR_STACK}}` = "Python / бібліотека requests", `{{CODE}}` = функція, що викликає `requests.get(url, retries=3)`.

**Вихід (фрагмент):**
```
### Галюциновані API — ВИСОКА впевненість
`requests.get()` не приймає ключовий аргумент `retries` — бібліотека `requests` не підтримує повтори нативно у виклику `get()`; повтори вимагають налаштування `Session` з `HTTPAdapter` і об'єктом `Retry` з `urllib3`, чи використання стороннього обгортача. Цей код видасть `TypeError` під час виконання, не мовчки проігнорує аргумент.
Виправлення: використай `requests.Session()` з підключеним `HTTPAdapter(max_retries=Retry(total=3))`, чи перевір за поточною документацією `requests`, чи новіша версія додала це — але з урахуванням заявленого контексту, цей виклик невалідний.
```

## Поради та варіації
- Для мови/бібліотеки, з якою ти сам не глибоко знайомий, явно попроси позначати все, у чому немає 100% впевненості, як "потребує ручної перевірки за офіційною документацією", а не впевнено стверджувати в будь-якому напрямку — це тримає рев'ю чесним щодо власної невпевненості.
- Поєднуй з фактичним запуском коду/тестів як базовою перевіркою галюцинованих API — реальна помилка виконання остаточна так, як жодна впевненість статичного рев'ю бути не може.
