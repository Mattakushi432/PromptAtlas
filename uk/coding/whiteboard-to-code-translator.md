## Опис
Перетворює описаний алгоритм (простою мовою, псевдокодом чи описом у стилі ескізу на дошці) на чистий, робочий код цільовою мовою — завдання перекладу, відрізняється від «Генератора задач для співбесід» (створює нову задачу) і «Ведучого мок-співбесіди» (інтерактивна практика співбесіди). Для швидкого переходу від "ось мій підхід" до фактичного робочого коду.

## Коли використовувати
- Опрацював логіку алгоритму на папері/дошці (чи описав усно в сесії практики співбесіди) і потрібно перетворити на реальний код, щоб перевірити, що він фактично працює.
- Маєш чітку ментальну модель підходу, але хочеш допомогу з перекладом на ідіоматичний код конкретною мовою замість ручного написання шаблонного коду.
- Рев'ю того, чи описаний підхід, коли стане конкретним кодом, дійсно обробляє випадки, які ти припускав.

## Промпт

```
Ти перекладаєш описаний алгоритм на чистий, робочий код цільовою мовою — вірний описаній логіці, не інший підхід, що випадково розв'язує ту саму задачу.

Опис алгоритму (проста мова, псевдокод чи кроки в стилі дошки): {{ALGORITHM_DESCRIPTION}}
Цільова мова: {{LANGUAGE}}
Сигнатура функції чи формат I/O, якщо вказано (необов'язково): {{SIGNATURE}}

Інструкції:
1. Перекладай описану логіку вірно — якщо опис має конкретний підхід (напр., "використай два вказівники, що рухаються назустріч один одному"), реалізуй саме цей підхід, не підміняй мовчки інший алгоритм, що розв'язує ту саму задачу, навіть якщо він ефективніший. Якщо помітиш, що описаний підхід має ваду, спочатку реалізуй його як описано, потім познач ваду окремо.
2. Використовуй ідіоматичні патерни для {{LANGUAGE}}, а не буквальну порядкову транслітерацію псевдокоду — напр., використовуй фактичні ідіоми ітерації/колекцій мови, а не вручну керуй індексами там, де мова має чистіший вбудований спосіб.
3. Якщо опис неоднозначний щодо конкретної деталі (напр., "відсортуй список" без вказання зростання/спадання, чи неясно, як обробляти нічию), зроби розумний вибір і явно зазнач припущення, а не мовчки обирай одну інтерпретацію.
4. Обробляй крайові випадки, на які опис натякає, навіть якщо явно не сформульовано (порожній ввід, ввід з одним елементом), якщо вони природні наслідки описаної логіки — але не додавай захисну обробку для випадків, які опис алгоритму фактично не потребує обробляти, оскільки це додало б логіку понад описану.
5. Використовуй чіткі назви змінних, що відображають фактичні ролі алгоритму (не `i`, `j`, `temp` для всього), якщо тільки сам опис не використовує саме ці назви і зміна їх не знизила б простежуваність до оригінального опису.
6. Якщо {{SIGNATURE}} вказує точну сигнатуру функції чи формат I/O, відповідай їй точно — переклад, що логічно коректний, але не відповідає потрібному інтерфейсу, фактично не використовний.
7. Після коду коротко сформулюй результуючу часову/просторову складність реалізованого алгоритму, щоб можна було підтвердити відповідність очікуванню з моменту, коли ти проєктував підхід.

Вивід: код у блоці з fenced-обгорткою, за яким слідує однорядкова примітка складності і будь-які позначені припущення.
```

## Змінні
- `{{ALGORITHM_DESCRIPTION}}` — алгоритм так, як описаний, у будь-якій формі, в якій він наразі існує. Обов'язково.
- `{{LANGUAGE}}` — цільова мова програмування. Обов'язково.
- `{{SIGNATURE}}` — потрібна сигнатура функції чи формат I/O. Необов'язково.

## Приклад
**Вхід:** `{{ALGORITHM_DESCRIPTION}}` = "використай два вказівники, що починають з обох кінців відсортованого масиву, рухаючись усередину, щоб знайти пару, що дає в сумі цільове значення", `{{LANGUAGE}}` = "Python", `{{SIGNATURE}}` = "def two_sum_sorted(arr: list[int], target: int) -> tuple[int, int] | None".

**Вихід (фрагмент):**
```python
def two_sum_sorted(arr: list[int], target: int) -> tuple[int, int] | None:
    left, right = 0, len(arr) - 1
    while left < right:
        current_sum = arr[left] + arr[right]
        if current_sum == target:
            return (left, right)
        elif current_sum < target:
            left += 1
        else:
            right -= 1
    return None
```
*(Складність: O(n) часу, O(1) простору — відповідає описаному підходу двох вказівників. Припущення: повертає індекси, не значення, оскільки тип повернення сигнатури натякає на пару позицій; познач, якщо натомість малися на увазі значення.)*

## Поради та варіації
- Якщо перекладаєш описаний підхід, у коректності якого не повністю впевнений, попроси також згенерувати кілька швидких тестових випадків на основі опису, щоб перевірити, що перекладений код дійсно поводиться як задумано, перш ніж на нього покладатися.
- Конкретно для практики співбесід зроби цей крок перекладу спочатку сам без допомоги, потім використай цей промпт лише для звірки свого перекладу з вірним еталоном — використання його для написання коду з самого початку пропускає практичну цінність.
